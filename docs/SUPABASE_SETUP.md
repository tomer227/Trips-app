# חשבונות משתמשים ב־Supabase

האפליקציה עובדת מלאה בלי חשבון. כשמחברים Supabase מתווספים: הרשמה וכניסה, סנכרון בין מכשירים של התכנון, היומן, ההוצאות, הצ׳קליסט והמקומות השמורים, וביקורות משותפות לקהילה.

## מה פרטי ומה ציבורי
| מידע | מי רואה |
| --- | --- |
| ביקורות שפורסמו | כולם, עם שם התצוגה (לא האימייל) |
| תכנון, יומן, הוצאות, צ׳קליסט, מקומות שמורים ומקומות שהוספתם | רק הבעלים (מוגן ב־Row Level Security) |
| "אני כאן", תמונות בביקורות | נשארים במכשיר |
| דיווחים על ביקורות | לא נגישים דרך ה־API, רק בדשבורד |
| מודעות "מחפשים שותף" | רק משתמשים מחוברים, עם שם התצוגה. נעלמות אחרי תאריך הסיום |
| הודעות למודעה | רק כותב המודעה ומי ששלח את ההודעה |

## הפעלה (חד־פעמית, בדשבורד של Supabase)
1. **צרו פרויקט** ב־[supabase.com](https://supabase.com) (או השתמשו בקיים).
2. **SQL Editor → New query.** בפרויקט חדש: הדביקו את כל התוכן של `supabase/setup_all.sql` (כל ה־migrations לפי הסדר) ולחצו **Run**. אם רואים "Success", הטבלאות וההרשאות נוצרו. בפרויקט שכבר הריץ את `0001_init.sql`, הריצו רק את ה־migrations החדשים מתוך `supabase/migrations/`.
3. **Authentication → URL Configuration:**
   - **Site URL:** כתובת האתר, למשל `https://<project-id>.web.app`.
   - **Redirect URLs:** אותה כתובת עם `/` בסוף, וגם `http://localhost:5173/` לפיתוח.
4. **Authentication → Providers → Email:** השאירו מופעל. מומלץ להשאיר **Confirm email** מופעל (אימות כתובת), ולהגדיר סיסמה מינימלית 8 תווים.
5. **Project Settings → API Keys:** העתיקו את **Project URL** ואת מפתח **anon public** (בפרויקטים חדשים: **Publishable**, מתחיל ב־`sb_publishable_`). שניהם עובדים.
   - **לעולם לא** את `service_role` או `sb_secret_...`. הם עוקפים את כל ההגנות.
6. **הפעילו באפליקציה:** בקובץ `.env.local` (לא נכנס ל־Git) הוסיפו:
   ```
   VITE_SUPABASE_URL=https://xxxx.supabase.co
   VITE_SUPABASE_ANON_KEY=eyJ...
   ```
   ואז בנו ופרסו מחדש (`npm run build`, או `npx firebase-tools deploy`). המפתחות נקלטים בזמן הבנייה.

בלי שני המשתנים האלה, מסך "החשבון שלי" מציג "החשבונות עוד לא הופעלו" והכל ממשיך לעבוד מקומית.

## אימיילים
ברירת המחדל של Supabase שולחת אימיילי אימות ואיפוס באנגלית ובמכסה נמוכה (כמה בשעה). לשימוש אמיתי:
- **Authentication → Email Templates:** תרגמו לעברית.
- **Project Settings → Authentication → SMTP Settings:** חברו ספק אימיילים משלכם (Resend, SendGrid ועוד) כדי להעלות את המכסה.

## מה נבדק
- **מסד הנתונים:** 12 בדיקות על Postgres אמיתי (PGlite) עם משתמשים שונים ואנונימי: מי יכול לקרוא, לכתוב, לערוך ולמחוק. הבדיקות מצאו ותיקנו באג בהסתרה האוטומטית של ביקורות.
- **הקוד:** בדיקות לסנכרון (מיזוג, מחיקות, שני מכשירים), לשירות ההתחברות (מול לקוח Supabase מדומה) ולמסך החשבון בדפדפן, עם תחליף בזיכרון.
- **לא נבדק:** מול פרויקט Supabase אמיתי (אין לי גישה אליו), ולכן אימייל אימות ואיפוס סיסמה בפועל דורשים בדיקה ידנית אחרי ההפעלה.

## מגבלות ידועות
- כששני מכשירים שינו את אותו פריט ממש (למשל אותה רשומה ביומן) בלי לסנכרן בינתיים, נשמר השינוי האחרון. הוספות ומחיקות משני המכשירים נשמרות.
- תמונות בביקורות לא עולות לענן בשלב הזה.
- אין עדיין כניסה עם Google (דורשת הגדרת OAuth בדשבורד).
- הסתרה אוטומטית של ביקורת מתרחשת אחרי דיווחים משלושה משתמשים שונים. אין עדיין מסך ניהול, וביקורות מוסתרות נבדקות בדשבורד (טבלת `reviews`, עמודת `hidden`).

## מחיקת חשבון
במסך "החשבון שלי" → "מחיקת החשבון". הפעולה מוחקת את החשבון, את הנתונים הפרטיים ואת כל הביקורות (פונקציית `delete_my_account`).
