# עדכון מקומות שבועי

כל יום שני ב־06:00 UTC (ובכל רגע ידנית) רץ תהליך ב־GitHub Actions (`.github/workflows/weekly-places.yml`) שפותח **Issue** בשם "דוח מקומות שבועי" ומסגר את הקודם.

## מה הדוח כולל
1. **בריאות:** האם המפתח, המכסות והחיוב של Google עובדים. אם לא, הריצה נכשלת (מייל מ־GitHub).
2. **בדיקת המקומות של הצוות** מול Google: סגורים לצמיתות/זמנית, מיקום שונה מאוד, או ש־Google לא מכירה כלל. ערים, שבילים ואזורים נבדקים רק לסגירה, כי Google מחזירה עבורם נקודה קרובה ולא את האזור.
3. **עד 25 הצעות למקומות חדשים** באזורי המפגש (אוכל, קפה, לינה, חיי לילה): מדורגים גבוה, עם מספיק ביקורות, פתוחים, ועוד לא הוצעו. הם מפוזרים בין הערים. **שום דבר לא נוסף לאפליקציה אוטומטית.**

## מה לא מתעדכן, ולמה
דירוגים, שעות פתיחה ותמונות נטענים חי מ־Google בכל פתיחת מקום, לכן תמיד עדכניים. תנאי Google אינם מאפשרים לשמור אותם במאגר, ולכן בין הריצות נשמרים **רק מזהי מקומות** (בענף `weekly-places-state`), כדי לא להציע אותו מקום פעמיים.

## הפעלה (חד־פעמית)
1. במאגר ב־GitHub: **Settings → Secrets and variables → Actions → New repository secret**. שם: `GOOGLE_MAPS_API_KEY`, ערך: המפתח.
2. **Settings → Actions → General → Workflow permissions**: לבחור "Read and write permissions".
3. **Actions → Weekly places update → Run workflow** להרצה ראשונה. אחר כך הוא רץ לבד כל שבוע.

בלי הסוד, התהליך מדלג בשקט.

## עלות
כ־180 בקשות בשבוע (בדיקה + חיפוש). התקרה נקבעת ב־`MAX_REQUESTS` (ברירת מחדל 220). בדקו את המחירים המעודכנים של Google ואת ההתראות התקציביות שהגדרתם.

## הרצה מקומית
```bash
GOOGLE_MAPS_API_KEY=... npm run weekly-places   # כותב את הדוח ל-.state/report.md
```
